# writing-plans 使用说明

> 将概要设计（HLD）和详细设计（LLD）转化为可执行的子任务清单，让 implementer 可以直接上手。Agent 执行细节以 [`SKILL.md`](./SKILL.md) 为准。

## 这个 Skill 是做什么的

从 `lld.md` 提取需要实现的类、方法、配置，拆分为可独立验证的子任务，标注依赖关系、判定并行度、定义每个子任务的验证方式，最终输出实现计划。本技能为计划编排，**不执行实际编码**。

- 主要产出：**`docs/artifacts/impl-plan.md`**
- 上游：`lld-author` 产出的 `lld.md`
- 下游：`implementer`（按计划编码）

## 适用场景

- LLD 设计完成后，进入实现准备阶段
- 功能交付工作流的"实现计划"步骤

## 前置条件

- `docs/artifacts/lld.md` 必须存在（不存在则停止并报告缺失）
- `docs/artifacts/hld.md` 建议存在（参考用）

## 执行流程

```
1. 拆分子任务   → 一个可独立验证的变更 = 一个任务（≤1 小时）
2. 标注依赖     → 前置依赖 / 软依赖 / 无依赖，画依赖图
3. 判定并行度   → 识别可并行任务组；并行度≥2 建议用 Git Worktree
4. 定义验证方式 → 编译/单测/集成/DDL/Lint
5. 输出实现计划 → 子任务清单表 + 依赖图 + 并行策略 + 执行顺序 + 风险
```

## 产出物

| 文件 | 说明 |
|------|------|
| `docs/artifacts/impl-plan.md` | 子任务清单、依赖关系图、并行策略、执行顺序、风险 |

## 关键约束

- 每个子任务必须可追溯到 `lld.md` 中的具体类或方法
- 禁止出现无法验证的子任务（如"优化代码结构"）
- LLD 中遗漏或不清楚的设计，标注为风险而非自行补充
