# harness-debug-logger 使用说明

> 记录 harness 工程运行时的完整轨迹，用于调试工作流执行过程。Agent 执行细节以 [`SKILL.md`](./SKILL.md) 为准。

## 这个 Skill 是做什么的

为每个工作流的每个步骤提供统一的日志格式，在步骤执行前后自动追加结构化条目，形成可回溯的执行轨迹。这是全局技能：除非 workflow YAML 显式 `debug: false`，每个步骤都应调用。

- 输出文件：**`{artifact_root}/workflow/harness-debug.md`**
- 通过 workflow YAML 中 `debug: true/false` 控制，默认启用

## 适用场景

- 工作流启动/完成
- 规则加载、资源冲突检测
- 技能调用、子代理派发、审查闭环、人工检查点
- 制品归档

## 记录的事件类型

| 事件 | 记录要点 |
|------|----------|
| 工作流启动 | 工作流名、任务、触发方式 |
| 规则加载 | 列出所有激活的 `.mdc` |
| 资源冲突检测 | **仅扫描 harness 自身配置**，检测职责重叠/定义矛盾/引用缺失/覆盖空白 |
| 技能调用 | 阶段、技能路径、输入/输出、引用文件 |
| 子代理派发 | 阶段、代理路径、模式、输入/输出制品 |
| 审查闭环 | 审查者、轮次 N/5、结果、处理 |
| 人工检查点 | 原因、决策摘要、状态 |
| 制品归档 | 归档路径、文件数 |

> 资源冲突检测**不扫描**业务项目源码/制品/配置——那由各阶段审查子代理负责。

## 关键约束

- 粒度为步骤级别，不记录代码行级细节
- 必录字段：时间戳、阶段、资源路径、输入摘要、输出摘要
- 与 `decision-log.md`、审查报告去重，只记摘要+引用
- 编码阶段每个子任务完成后必须**立即追加**日志，禁止事后补录
- 日志本身也是制品，随其他制品归入 `archive/`
