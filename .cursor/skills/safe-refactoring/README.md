# safe-refactoring 使用说明

> 确保重构过程中行为不变，每一步都可验证、可回滚，绝不夹带功能变更。Agent 执行细节以 [`SKILL.md`](./SKILL.md) 为准。

## 这个 Skill 是做什么的

按 `refactoring-plan.md` 逐步执行重构：每步只做一种操作、执行后立即测试、测试失败就回滚到上一个绿色状态，并把每步状态回写到计划文件。核心是用"小步 + 频繁验证"把重构风险降到最低。

- 上游：`refactor-plan` 产出的 `refactoring-plan.md`

## 适用场景

- 执行 `refactoring-plan.md` 中的重构步骤时
- 任何涉及代码结构调整但不改变行为的场景

## 核心原则

1. 每步只做一种操作（不混合"提取方法"和"重命名"）
2. 每步后立即运行相关测试
3. 测试红了立即回滚到上一个绿色状态
4. 绝不夹带功能变更、bug 修复或优化

## 执行流程

```
1. 确认前置条件 → 测试全绿、计划存在、覆盖率足够（不足则先补测试）
2. 逐步执行     → 执行单一操作 → 测试 → 通过则继续 / 失败则回滚分析
3. 单步操作规范 → 提取方法/搬移方法/提取类/重命名 各有标准步骤
4. 验证完整性   → 全量测试 + 公共接口签名对比 + diff 可追溯
```

## 禁止事项

- 禁止在重构提交中包含功能变更
- 禁止"顺手"修复 bug
- 禁止跳过测试执行
- 禁止一次提交包含多种重构操作
- 禁止修改测试断言（除非重构了测试辅助方法签名）

## 回滚策略

| 场景 | 操作 |
|------|------|
| 单步测试失败 | `git checkout -- .` 撤销当前步 |
| 多步后发现问题 | `git revert` 到最后一个绿色提交 |
| 重构后回归失败 | 逆序逐步 revert 定位问题步骤 |
