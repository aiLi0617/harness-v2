# tdd-bugfix 使用说明

> 以测试为驱动的 Bug 修复流程：先写失败测试证明 Bug 存在，再写最小修复让测试通过。Agent 执行细节以 [`SKILL.md`](./SKILL.md) 为准。

## 这个 Skill 是做什么的

在根因确认后进入修复阶段，按 4 个步骤保证修复的正确性与不引入回归：编写失败测试 → 实施最小修复 → 运行全量回归 → 审视修复代码质量。

- 上游：`systematic-debug` / `bug-analyst` 产出的 `docs/artifacts/root-cause.md`

## 适用场景

- 根因已确认，进入修复阶段
- 需要保证修复正确且不引入回归

## 前置条件

- `docs/artifacts/root-cause.md` 存在且内容完整（含根因位置、触发条件、建议修复方向）
- 项目测试框架可正常运行（JUnit / TestNG 等）

## 执行流程

```
1. 编写失败测试   → 精确命中触发条件，运行确认失败（红）
2. 实施最小修复   → 只改根因位置，最小改动让测试变绿
3. 全量回归测试   → 模块测试 + 项目测试，确认无副作用
4. 审视代码质量   → 异常/空值/资源/线程/日志/硬编码/重复/性能
```

## 禁止事项

- 不写测试直接修复
- 修复范围超出根因
- 测试写在修复之后
- 忽略与修复相关的回归测试失败
- 改测试断言让其通过（断言正确行为时）
- 一次提交混入无关改动
